# 接入方式

1. **启动**：调用官方 `bin/cortico.mjs`；模板清单与创建调用官方 launcher 的命令行子命令。
2. **控制**：通过官方公开 WebUI API 读取状态、暂停和关闭角色。
3. **网页**：每个角色有独立代理端口。直接访问角色入口时，由管理器返回一个跳转页，进入管理中心并保留角色与页面位置；管理中心内嵌的原版 HTML 原样转发。HTTP/WebSocket 代理处理管理登录、原生 Cookie 和允许管理入口嵌入的 CSP 响应头，不修改官方页面文件。
4. **数据**：托管角色放在自己的 `deployments/`，扩展放在自己的 `extensions/`。不读取或接管 Cortico 目录内已有部署。

管理密码只以加盐哈希保存。浏览器仅持有管理登录 Cookie；原版后台的随机密码和 Cookie 留在管理器进程内，角色间的浏览器存储由独立端口隔开。退出登录与改密码会撤销各入口会话及 WebSocket，角色继续运行。

## 复制范围

**按需复制（默认）**保留设定、提示词与外观，记忆、会话、历史、定时任务、待处理事件、World 状态和外部连接逐项选择。已验证内置 Cormini、CortiV、Corti Soulmate；外部连接默认不选。复制会话时携带关联事件和图片，复制待处理事件时包含其依赖的数据。

**完整本地克隆**先正常关闭来源，再复制整个部署目录，包括未知插件目录、数据库文件、`.env` 和连接配置。无需逐个 World 编写复制规则。端口、进程锁、WebUI 密钥和重启标记重新生成；服务进程日志不复制。完成后恢复来源原状态，副本保持停止。

完整克隆的边界：
- 部署目录内的普通文件整体复制；内部符号链接重新指向副本，外部链接保留引用并列入检查清单。
- 部署目录外的数据库、服务端游戏进度、模型供应商及已安装扩展仍共用原位置；不自动下载或复制外部数据。
- Core 的 `paths.memory/data` 需要位于部署目录内，支持自定义本地路径；外置时先迁回再克隆，避免副本直接写来源的记忆与运行状态。

复制结果页和角色卡片提供**启动前检查**：按 World 列出账号/凭据、端口、外部路径等配置项名称，不展示密钥，不连接外部服务。副本停止时可直接切换 World 的启用/停用状态，自动保存且保留数据；运行时锁定开关并提示先关机。仅暂停 AI 不会阻止 World 启动连接，因此应在首次启动前检查。对于第三方私有字段，清单提供通用检查提示。

只有按需复制需要分类规则。规则位于管理器数据目录的 `copy-rules.json`，例如：

```json
{
  "my-bot": {
    "memoryDir": "workspace",
    "dataDir": "data",
    "settingsInMemory": ["CONSTITUTION.md"],
    "worldState": ["my-game"],
    "connections": {
      "my-game": {
        "label": "My game",
        "keys": ["accountId", "token"],
        "secrets": ["MY_GAME_API_KEY"]
      }
    }
  }
}
```

按需复制中，未知 World 的配置作为外部连接整体选择；`.env` 只复制规则声明且选中的密钥。未分类的 World 本地数据会列出提示。完整克隆则整体保留这些文件。
